## What this repo is

- Global shell config for macOS (Apple Silicon). Five managed files: `zshenv`, `zprofile`, `zshrc`, `profile` (POSIX login shells), and `mise/config.toml` (global mise pins).
- **These files are symlinked into `$HOME`** (`.zshenv`, `.zprofile`, `.zshrc`, `.profile`, `.config/mise/config.toml`). Editing anything under `$HOME` directly is wrong — it will be overwritten by the next `ln -sfn`. Change the repo file.
- Re-link after a fresh clone:

  ```sh
  ln -sfn "$PWD/zshenv"   "$HOME/.zshenv"
  ln -sfn "$PWD/zprofile" "$HOME/.zprofile"
  ln -sfn "$PWD/zshrc"    "$HOME/.zshrc"
  ln -sfn "$PWD/profile"  "$HOME/.profile"
  mkdir -p "$HOME/.config/mise"
  ln -sfn "$PWD/mise/config.toml" "$HOME/.config/mise/config.toml"
  ```

- macOS zsh 5.9 (system). Not a plugin manager, not oh-my-zsh. No build step, no tests, no CI.

## File responsibilities (do not blur these)

- `zshenv` — sourced for **every** zsh invocation, including non-interactive `zsh -c`, cron, ssh commands, and build tools shelling out. Keep it minimal: only `$HOME/.cargo/env` so `cargo`/`rustc` exist outside a login shell.
- `zprofile` — login shells. PATH construction, env exports, toolchain bootstrap. Must stay free of prompt logic and interactive functions.
- `zshrc` — interactive non-login shells. Functions, aliases, prompt, completions, keybindings, history options, plugin loading. **No PATH or env writes**; all of those live in `zprofile`.
- `profile` — POSIX `/bin/sh` / bash login shells. Only `$HOME/.cargo/env`; zsh never reads it.
- `mise/config.toml` — global mise pins, symlinked to `~/.config/mise/config.toml`.

## Conventions / Gotchas

- **Never commit username-specific absolute paths.** Use `$HOME` or an env var. The old hardcoded Hutch/Unity/Docker entries at the tail of `zshrc` were consolidated into `zprofile` as `$HOME`-relative `add_to_path` calls; don't reintroduce them.
- **`add_to_path()` is the only sanctioned way to touch PATH** in `zprofile`: it no-ops on a missing directory and de-dupes against the existing PATH. Use it, not bare `export PATH=...`.
- **Never add a relative or project-local directory to PATH.** This was a deliberate security fix (`0239a87`, PR #2): a relative entry lets the current directory shadow trusted tools. Project-local binaries are resolved by package-manager scripts instead.
- **Homebrew owns system packages; mise owns every dev runtime and dev CLI.** Activated *after* brew and `$HOME/.local/bin`, then `hash -r` rehashes so mise shims come first. Global config `mise/config.toml` (symlinked to `~/.config/mise/config.toml`) is the source of truth for Java/Node/Python/Bun plus act, actionlint, cargo-nextest, circleci, gh, gitleaks, glab, osv-scanner, pipx, ruff, sccache, shellcheck, solidity (solc), supabase, uv, zizmor, and npm CLIs (`npm:` backend). Homebrew is limited to system packages, services, and build libraries. Do not reintroduce nvm, `brew python@3.11`, `npm i -g`, `bun add -g`, `pipx install`, `cargo install`, or `uv tool install` for dev CLIs — add them with `mise use -g <tool>` and pin the version. Keep `allow_builds` entries for opencode/railway postinstall scripts.
- `.mise.toml` at the repo root is an empty `[tools]` marker — this stack uses globals in `mise/config.toml`. Don't add pins here.
- **Shell startup is perf-sensitive; the existing guards are deliberate.** `brew --prefix` was hardcoded to `/opt/homebrew` (~0.3s saved), the `compaudit` scan is skipped in favour of `compinit -C` when `.zcompdump` is under 24h old, and `thefuck` is lazily self-`unfunction`ed on first use (~1s saved). Don't "clean these up" into eager calls.
- **Plugin load order is load-bearing:** syntax-highlighting → history-substring-search → autosuggestions, and all three after `compinit`. `compinit` must run *after* every `fpath` entry is registered (Docker completions, `$HOME/.bun`, `/opt/homebrew/share/zsh-completions`). `history-substring-search` needs `bindkey` lines that come after the plugin sources.
- `alias rmdir='rm -rf'` is **not** the real `rmdir` — it force-deletes recursively. That is intentional but surprising; keep the inline comment so it isn't "fixed" by someone who assumes it's a typo.
- `cleardir`, `gitreset`, and `gitupstream` are guarded (`y/N` confirm, or explicit args). Keep confirmation prompts on any new destructive function.
- `zsh -n <file>` is the syntax check; `re-source` (sourced from `zshrc`) reloads `zprofile` + `zshrc` without losing your cwd, and `zprofile`/`zshrc` aliases open these files in VS Code.
- Machine-specific hosts stay in env vars (`PI_SSH_TARGET` for `ssh-pi`). Don't hardcode them.
- `Dracula.terminal` and `terminal_preview.png` are Terminal.app artifacts — leave them alone.
